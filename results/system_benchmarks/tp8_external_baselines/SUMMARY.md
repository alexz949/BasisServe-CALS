# TP8 External Baselines: ShadowKV and STAR-KV Complete

The ShadowKV request/steady comparison is complete: 108/108 formal trials succeeded, with no OOM or other failure. The STAR-KV V-only context grid is complete: 35/36 succeeded and one cache-state OOM is preserved. Its separate fixed-16K batch sweep completed 14/18 trials, with four cache-state OOMs. The 4K TP8 runs under the `smoke/` folders validate the runners only; their measurements are not paper results.

## Confirmed Scope

- ShadowKV: Llama-3.1-8B-Instruct, TP8, global pre-RoPE K SVD, rank 160, chunk 8, sparse budget 2048, official CPU V offload. Compare with Dense and the frozen full-scan Basis-joint V96 implementation.
- STAR-KV V-only: Qwen3-8B-Base, V-adaptive-50 versus BasisKV V64 only. The user-confirmed 36-trial grid uses six lengths, three batches, two arms, and preselected cohort 0; it has no cross-cohort variance estimate. This scope overrides the five-arm Llama configuration and three-cohort preference in the original English attachment.
- Environment: `basis`; the same eight NVIDIA L40S GPUs. No Slurm is available on this machine.
- Timing: BasisKV projection, routing encoding, and cache writes count toward prefill and total request latency. The separate construction category is restricted to ShadowKV-specific gather/SVD/redistribution/preparation; its absence in BasisKV does not mean free encoding. Interleaved construction must not be counted twice.
- No final-result tuning, substituted algorithms, omitted failures, or synthetic checkpoints.

## Current Status

- The preceding 144-trial frozen BasisKV grid has completed: 132 successes and 12 prefill OOMs. All 1056 successful rank results validated, and all 1629 archived source files remained byte-identical. Its implementation and environment were not changed for these prototypes.
- ShadowKV factor, native-cache, and short real-text model GPU correctness tests passed. In the 4K/B1 model check, all nine generated IDs matched the single-GPU reference; maximum logits relative error was 1.689821%, and minimum selected-set overlap was 96.875%. Prefill used four SVDs per rank; decode used none.
- The request runner passed 4K/B1 smokes for ShadowKV, Dense, and BasisKV; the Dense/Basis generated IDs match the preceding frozen runner for all 128 output tokens. ShadowKV also passed a 4K/B8 request smoke and an independent 4K/B1 steady window with 16 conditioning and 128 measured steps. All 108 formal trials (64K/128K, B1/B4/B8, three cohorts, three arms, request and steady modes) completed without failure, and the eight-rank raw-result validator passed every trial. The formal CSVs and request-breakdown PDF/PNG are under `shadowkv/` and `plots/`.
- At ~128K/B8, the median-total-cohort request took 95.624 s for BasisKV and 167.939 s for ShadowKV; 59.188 s of ShadowKV's additive time was online construction, including 47.724 s SVD. These are instrumented TP8 request times, not isolated kernel times. At the same workload, ShadowKV's median max-rank request peak was 39.764 GiB allocated and its decode-ready allocation was 14.055 GiB; its pinned CPU V capacity was 63.5 GiB across eight ranks. It did not OOM in this grid.
- Thirteen CPU-only request-timing accounting tests passed, covering nonoverlapping construction, owner/nonowner waiting, first-token versus decode-ready boundaries, and invalid rank records. These synthetic timestamps are not measured latencies.
- FlashAttention 2.8.3.post1 was built from unchanged upstream source, installed, and verified by import and the TP8 GPU model smoke. The first build failed because the existing nvcc 13.4 and CUDA runtime headers 13.0 were incompatible; that failure remains in the log. The successful second build used an isolated matching CUDA 13.0 toolchain. Torch remains 2.13.0+cu130. The model adapter requires upstream `flash_attn_with_kvcache`; it has no alternate decode backend.
- The STAR-KV adaptive-V `fused.pt` was downloaded from pinned HF revision `0ef83dff27205b131c82df6d62636129e9dac7b9` and its V-factor shapes matched the exported rank metadata. Actual retention is 54.0473%, above the nominal 50% budget; this export is not eligible for a strict V50 comparison. The independent Qwen3 TP8 V-only runner used 4096-token chunked prefill for both arms. Its 36 formal trials comprise 35 successes and one STAR-KV cache-state OOM at 130048/B8; all eight ranks failed on a 1.81 GiB V-cache allocation before prefill. At 98304/B8, decode-ready max-rank NVML process memory was 38.102 GiB/GPU for STAR-KV and 16.217 GiB/GPU for BasisKV V64. BasisKV completed 130048/B8 at 19.451 GiB/GPU. No OOM point is assigned a measured decode-ready value. See `starkv_v_only/README.md` and `starkv_v_only/SUMMARY.md`.
- The separate 16K prefill + 128 output-token TP8 sweep used 256-token prefill chunks and B1/B2/B4/B8/B16/B32/B64/B128/B256. BasisKV V64 completed through B128 (33.160 GiB/GPU decode-ready max-rank NVML) and first OOMed at B256. STAR-KV V-only completed through B32 (25.867 GiB/GPU) and first OOMed at B64. All four failed trials OOMed during cache-state allocation, before prefill. These are single-cohort capacity outcomes, not speed or quality comparisons. See `starkv_v_only/batch_sweep_16k/README.md` and its `SUMMARY.md`.
- Uploaded instructions are preserved under `inputs/`. The latest Chinese clarification takes precedence where it conflicts with the attachment.

The STAR-KV grid uses one preselected cohort per configuration, so its memory values lack cross-cohort variance estimates. Contexts above the Qwen3 native 32768-token limit are memory-only stress tests. These external-baseline files are separate from the 32-file publication of the earlier frozen grid.
