2. FIGURE 2: Throughput under K offload
============================================================

Goal:
Show the deployment consequence of sparse K access when historical K
is placed in host memory.

This is NOT the pure sparse-compute benchmark.
This is a serving / data-movement benchmark.

Use 64K as the main context because it provides a clean batch sweep.

Suggested caption title:
"Long-context decode throughput under K offload."

------------------------------------------------------------
2.1 Methods
------------------------------------------------------------

Compare three methods:

A. Dense-local
- full exact K/V GPU-resident
- dense full-context attention

B. Dense-K-offload
- historical exact K in pinned/mapped CPU memory
- full V remains GPU-resident
- each layer/step retrieves the full historical K needed for dense attention
- use preallocated staging
- no per-step malloc/free
- reasonable async-copy implementation

C. BasisKV-K-offload
- historical exact K in pinned/mapped CPU memory
- full V128 and routing state GPU-resident
- full-scan B16R16 / Page32
- 1,984 routed tokens + 64 recent tokens
- persistent GPU K slots
- fetch only selected/missing exact-K pages

This is a deployment comparison.
Do NOT describe it as a quality-equivalence experiment.
